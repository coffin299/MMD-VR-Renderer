### 修正 / Fixed
- JA: **完了ダイアログが「HW不可」と誤表示する**: HEVC NVENC成功＋巨大フレーム縮小だけのときもHW失敗に見えていた文言を修正
  EN: **Done dialog falsely said HW unavailable**: clarify wording when HEVC NVENC succeeded and only oversized frames were scaled
- JA: **8Kキャプチャ中にMMEがGetViewportで8K作業RTを再確保する**: GetViewportをバックバッファ寸法に偽る。MME連鎖時の推奨面は4096止め
  EN: **MME re-allocated 8K work RTs from GetViewport during capture**: lie GetViewport as backbuffer size; MME-chained face suggest caps at 4096
- JA: **ネイティブ8KでVRAMが16GBまで膨れる**: screenWidthを8Kにせず、MMEが見るviewportはバックバッファ寸法のまま／capture RTだけ8K
  EN: **Native 8K blew VRAM to 16GB**: leave screenWidth alone so MME keeps backbuffer-sized viewports; only the capture RT is 8K
- JA: **ネイティブ8K中の毎フレーム8Kダウンサンプルを抑止**: MMD録画用の巨大SYSTEMMEM読取をフックでスキップ
  EN: **Skip per-frame 8K downsample during native capture**: hook out MMD's huge SYSTEMMEM recorder readback
- JA: **MSAA有効時にネイティブ8Kが gate busy で起動しない**: キャプチャ中だけ captureSurface ゲートを0に退避／復元
  EN: **Native 8K refused with MSAA (gate busy)**: temporarily force the captureSurface gate to 0 during capture and restore it
- JA: **ネイティブ8KがMME Resetで即落ちする**: スワップチェインは触らず、8192のオフスクリーンRT+Depthだけを録画スロットへ載せる
  EN: **Native 8K instant-crashed on MME Reset**: leave the swapchain alone; attach an 8192 offscreen RT+depth to the recorder slots only
- JA: **ネイティブ8KのMME ResetがPresent中に即落ちする**: ResetをPresent完了後へ移し、フック済みMMEプロキシ経由でのみ実行
  EN: **Native 8K MME Reset crashed inside Present**: run Reset only after Present returns, and only through the hooked MME proxy
- JA: **ネイティブ8K Reset直後にMMEが壊れて落ちる**: FrameDriver中のPostDeviceResetをやめ、Present直前にフック済みMMEデバイス経由でResetするよう変更
  EN: **MME broke and MMD crashed right after native 8K Reset**: stop PostDeviceReset inside FrameDriver; Reset through the hooked MME device just before Present
- JA: **ネイティブ8K初期化中にMMDが落ちる／ジョブが早期中止する**: 高解像度RTの生成・bind・viewport更新が完了する前に開始成功を通知していた競合を解消
  EN: **MMD crashed or the job aborted during native 8K startup**: wait to report activation until high-resolution RT creation, binding, and viewport update have completed
- JA: **「8K」なのに 772² の画面を拡大していた**: 出力サイズダイアログだけに頼らず、MMD 9.32 のAVI録画用ネイティブ高解像度RT生成・Reset経路を使って完成カラー面を取得（AVIファイルは作成しない）。面サイズ未満の入力は拡大せずジョブを拒否
  EN: **“8K” was upscaling the 772² viewport**: use MMD 9.32’s native AVI-recording high-resolution RT/reset path to read the completed color surface without creating an AVI; reject undersized inputs instead of upscaling
- JA: **右下の Local XYZ 操作ギズモがキャプチャに残る**: MikuDanceStudio 移植知見どおりスプライト帯は `playbackActive` が 0 のときだけ出る。状態を先行変更せず、実際のスプライト生成関数内でだけゲートを立てて描画自体を止める（画素マスクは保険）
  EN: **Lower-right Local XYZ gizmo still in captures**: per MikuDanceStudio, the sprite strip draws only when `playbackActive` is 0; gate it inside the actual sprite producer instead of changing state ahead of the paint (pixel mask kept as fallback)
- JA: **最初の面だけ Local XYZ が消え、後続の面へ再混入する**: 面キャプチャ完了直後ではなく、ワーカーが面を受け取るまで操作ギズモ抑制を維持
  EN: **Local XYZ disappeared only on the first face then leaked into later faces**: keep gizmo suppression active until the worker consumes each captured face
- JA: **8K の最初の面で Present 待機が10秒で失敗する**: 8192² は最大60秒、4K級は最大30秒まで MMD/MME の高解像度描画完了を待機
  EN: **First 8K face timed out after 10 seconds waiting for Present**: allow up to 60 seconds for 8192² and 30 seconds for 4K-class MMD/MME rendering
- JA: **8Kなのにぼやける／UI混入／右目欠け**: ray-mmd の HDR カラー面ではなく R32F の効果／深度面を取得して低解像度フォールバックになっていた。完成済みカラーRTを HDR 形式のまま読み出し、残る Local XYZ 操作ギズモを除去。右目が大きく壊れた場合は再キャプチャし、直らなければモノ化せずフレームを拒否
  EN: **Soft 8K / UI leak / broken right eye**: captured ray-mmd R32F effect/depth targets instead of completed HDR color; read back completed HDR color, remove the remaining Local XYZ gizmo, and recapture a damaged right eye instead of converting to mono
- JA: **8Kなのにぼやける**: ウィンドウ(~772²)を拡大していた。MMD「出力サイズ」を面解像度(最大8192)に設定して実キャプチャ
  EN: **Soft “8K” output**: was upscaling the ~772² window; now sets MMD output size to face res (cap 8192) for real capture
- JA: **8K ステレオ MP4 がディスク満杯で落ち、H.264 に見えてしまう**: 空き不足を事前検知／再試行停止し、巨大解像度でも HEVC NVENC→libx265 を維持
  EN: **8K stereo MP4 dies on full disk / looks like H.264**: preflight free-space check, stop retries on ENOSPC, keep HEVC NVENC→libx265 for huge frames
- JA: **CI の unit test が出力なしで exit 1**: 永続 Parallel プールの joinable スレッドが静的破棄で `std::terminate` していた
  EN: **CI unit tests exit 1 with no output**: joinable Parallel pool threads called `std::terminate` on static teardown

### 修正 / Fixed
- JA: **NVENC が常に「listed-fail」**: smoke-test が 128×128 で最小寸法未満だったのを 512×512 に。明示 NVENC 時は HW 上限内へ縮小して hevc_nvenc を維持
  EN: **NVENC always listed-fail**: smoke-test used 128×128 below NVENC minimum — now 512×512. Explicit NVENC scales into the HW cap and stays on hevc_nvenc
- JA: **ステレオ8K MP4が libx264 に落ちて失敗**: 30720×7680 は HEVC Level7.2 超過で libx265 が拒否→無意味な H.264 再試行。上限内へ縮小して H.265 のまま出力（PNGはフル解像度のまま）
  EN: **Stereo 8K MP4 fell to libx264 and failed**: 30720×7680 exceeds HEVC Level 7.2 so libx265 refused, then useless H.264 retry. Scale into the limit and stay on H.265 (PNGs remain full-res)
- JA: **左目面の直後に必ず落ちる**: `debug_faces` 自動保存が面バッファを RGB に破壊変換 → 正距円筒投影がバッファ外読み。自動ダンプ停止＋const 書き込み、MMD出力サイズ変更も当面スキップ
  EN: **Crash right after left-eye faces**: auto `debug_faces` dump packed face buffers to RGB in-place, then equirect read past the end. Disable auto-dump (const write only); skip MMD output-size changes for now
- JA: **開始直後に MMD が落ちる（VRAM/RAM ほぼ未使用）**: ステレオで左目投影と右目キャプチャを同時実行していたのをやめ、MMD 出力サイズは当面 4096 にクランプ。ログは `mmd_vr_renderer.log`、WER は `d3d9.dll` の c0000005
  EN: **MMD crashes right after start (little VRAM/RAM use)**: stop overlapping left-eye project with right-eye capture; clamp MMD output size to 4096 for now. Log: `mmd_vr_renderer.log`; WER: c0000005 in `d3d9.dll`
- JA: **RAM/VRAM に余裕があっても長時間でクラッシュ**: 巨大キャプチャ RT の毎フェイス Create/Release と `EvictManagedResources` 連打をやめ、投影用ワーカーをスレッドプールで再利用。面サイズ固定ステージ、pool 解放を Present スレッドへ遅延、マーカー除去のフル画像コピー廃止
  EN: **Crashes after a while despite free RAM/VRAM**: stop per-face RT thrash and mid-job Evict; persistent projection pool; face-fixed staging; defer pool Release to Present thread; ROI-only marker repair (no full-frame copies)
- JA: 設定ダイアログをコンパクト化（9pt フォント＋レイアウト詰め）。注記は2行のまま
  EN: Compact settings dialog (9pt UI font + tighter layout); notes still wrap to 2 lines
- JA: PNGキュー自動上限を緩和（空きRAMの約20%／最大12、高RAMでは8Kでも複数枚可）
  EN: Relaxed auto PNG queue (≈20% free RAM / up to 12; multi-frame OK on high-RAM 8K)
- JA: **CI**: `windows-latest` が VS 2026 のみになり VS2022 ジェネレータ固定で configure 失敗 → CMake 自動検出に変更
  EN: **CI**: `windows-latest` ships VS 2026 only; stop pinning VS2022 generator — let CMake auto-detect`
- JA: **長時間 8K ジョブの RAM/ディスク**: PNG キュー自動上限、不透明フレームの RGB PNG、クラッシュ後の PNG ギャップ再開
  EN: **Long 8K jobs RAM/disk**: auto PNG queue cap, opaque RGB PNGs, resume from PNG gaps after crash
- JA: **巨大フレームの HW エンコード失敗**: H.265(HEVC) 優先プローブとフォールバックダイアログ
  EN: **HW encode fails on huge frames**: prefer H.265 (HEVC) probe with fallback dialog
- JA: **キューブマップで ray-mmd が落ちる／Present 待ちタイムアウト**: GetTransform が影用 ortho を壊さないよう透視投影のみ差し替え。面キャプチャ待ち中に再描画を促す。面カメラの near/far は MMD 観測値を優先
  EN: **ray-mmd crash / Present wait timeout on cubemap**: replace perspective GetTransform only (keep shadow ortho); nudge redraw while waiting; prefer observed MMD near/far for face cameras
- JA: **レンダリング中だけ ray-mmd が破綻**: 面キャプチャ中はオフスクリーン透視パスも含め VIEW/透視PROJを面カメラで統一。面向きをカメラ前方基準へ。面行列未適用の Present はキャプチャしない
  EN: **ray-mmd breaks only while rendering**: unify VIEW/perspective PROJ on offscreen passes too; face dirs from camera forward; skip Present until face matrices applied
- JA: **MP4 に音声 mux**: MMD 読込 WAV を UI 自動検出／手動指定し、開始フレーム位置から AAC で載せる
  EN: **Audio mux into MP4**: auto-detect or browse MMD WAV; mux AAC from the start-frame offset
- JA: **YouTube VR メタデータ**: Google Spherical Video UUID を MP4 に注入（VR180 crop / VR360、ステレオ left-right）
  EN: **YouTube VR metadata**: inject Google Spherical Video UUID (VR180 crop / VR360, stereo left-right)
- JA: **アニメがフレーム0のまま**: キャプチャ前に MMD フレーム入力欄へシークしてポーズ評価
  EN: **Animation stuck on frame 0**: seek MMD’s frame edit before capture so pose evaluates
- JA: 進捗ダイアログが MMD を Disable しないよう変更（シーク／評価を阻害していた）

  EN: `MMDVR_ISOLATE=1..3` diagnostic switch to disable capture stages stepwise
